# Mnemosyne Protocol — Pilot Demo Package

**Version:** pilot_demo_v1  
**Source:** Live Unreal Engine 5 editor execution through the Mnemosyne Gate  
**Package Type:** Technical pilot evidence package

---

## Overview

This package contains two short, reproducible sessions captured from a live Unreal Engine workflow connected to the Mnemosyne Gate.

The purpose of the package is simple:

- show what an approved render session looks like
- show what a blocked render session looks like
- demonstrate that certification is issued only when the full session passes required checks
- demonstrate that non-compliant output is stopped before certification can be issued

This is an evidence package, not a marketing deck. It is intended for technical evaluation.

---

## 01_PASS_SCENARIO

This folder contains a session in which all submitted frames passed the Gate.

Included artifacts show:
- the session manifest
- the submitted frame set
- the certified passport issued for the session
- the session summary produced during evaluation

What this demonstrates:

- the pipeline can evaluate a render session against the Gate
- compliant output can move forward
- certification is issued only after the required checks pass for the session
- the result is captured as a machine-readable artifact, not as an informal manual approval

---

## 02_FAIL_SCENARIO

This folder contains a session in which one submitted frame violated policy.

Included artifacts show:
- the session manifest
- the blocked session record
- the rejection evidence generated by the Gate
- the absence of a certified passport for that session

What this demonstrates:

- the pipeline does not rely on partial trust
- a blocking violation stops certification for the session
- non-compliant output does not receive a downstream approval artifact
- the rejection is recorded as evidence, not silently dropped

## What `Mnemosyne_Certified_Passport.json` Represents

`Mnemosyne_Certified_Passport.json` is the certification artifact created only for a session that passes the required checks.

Its role is straightforward:

- identify the evaluated session
- bind the session to its approved output set
- provide a clear approval artifact for downstream systems and teams
- separate approved output from output that was evaluated but not cleared

In practical terms, it is the answer to a production question:

**Was this session cleared by the Gate, or not?**

---

## Why Fail-Closed Matters

The operational risk in high-throughput pipelines is not only bad output.  
The larger risk is uncertain output moving downstream because no system stopped it at the decision point.

Mnemosyne is designed around a fail-closed model:

- compliant sessions receive a certification artifact
- non-compliant sessions do not
- blocking conditions stop certification instead of allowing ambiguous output to pass through

For a studio pipeline, that means the decision is explicit.  
The system does not treat “not yet rejected” as “approved.”

## What This Package Proves

This package demonstrates:

- a live Unreal Engine editor path connected to the Mnemosyne Gate
- approval on pass
- blocking on fail
- generation of clear evidence artifacts for both outcomes
- a certification model tied to session-level evaluation, not informal review

## What This Package Does Not Claim

This package does not claim:

- full studio-wide deployment
- final product UI or final production tooling
- coverage of every policy type or every pipeline environment
- replacement of all downstream review functions

It is a pilot demonstration of a fail-closed admission and certification layer operating on a real editor workflow.
